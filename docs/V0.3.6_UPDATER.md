# Veylor V0.3.6 — atualização Windows com recuperação (beta)

**Estado:** implementação em branch de teste; não significa que há uma release aprovada.
A V0.3.6 depende da branch V0.3.5 (PR #3). O Android/Play Store continua
separado. Nenhum certificado Authenticode é exigido para gerar a beta, mas sem
certificado o Windows pode advertir que o editor é desconhecido.

## Primeira instalação

- A V0.3.5 não contém o novo atualizador externo. Instale **manualmente** uma
  V0.3.6 aprovada uma vez; o atualizador integrado atenderá às versões futuras.
- O backend `/api/updates/windows` precisa anunciar um build **maior** do que
  o instalado e apontar para a tag `vX.Y.Z-beta.N` da **Release oficial**
  `night02/discord2`. Links para Actions continuam abrindo a página
  manualmente, sem execução dentro do aplicativo.
- Apenas Releases **publicadas, não draft, marcadas prerelease**, com o EXE e
  `SHA256SUMS.txt`, podem ser instaladas no aplicativo.

## Fluxo em Windows

1. O usuário escolhe baixar no app. O cliente consulta a API pública do GitHub
   para a tag exata indicada na API Veylor **sem enviar sessão/token**.
2. Valida repo, tag, nomes, tamanhos, URLs e HTTPS. Só acompanha redirecionamentos
   de assets ao CDN do GitHub, sem aceitar hosts arbitrários.
3. Baixa `SHA256SUMS.txt`, escolhe exatamente uma entrada com o nome esperado,
   baixa o EXE em uma pasta temporária e compara tamanho e SHA-256 em disco.
   Erros, interrupções e downloads cancelados não instalam nada.
4. Exibe o resultado e solicita uma **segunda confirmação expressa** para
   instalar. Nenhum arquivo é executado só porque uma atualização foi detectada.
5. Copia `veylor-updater.exe` para a pasta de staging, inicia-o separadamente,
   fecha o Veylor e espera o PID anterior encerrar.
6. O helper **revalida o SHA-256**, renomeia o diretório de instalação antigo
   para um backup de rollback no mesmo volume e executa o novo Inno Setup em
   modo silencioso. Confere código de saída, `veylor.exe` e
   `veylor-version.txt` correspondente à versão solicitada.
7. Se o setup falhar ou a verificação da versão não passar, o helper remove os
   arquivos parciais e **restaura** o diretório anterior e o executável antigo,
   registrando tudo em `update-result.txt` dentro da pasta temporária.
   Se o instalador travar (timeout), **não** mexe na pasta até investigar, pois
   o processo pode ainda estar escrevendo arquivos.
8. Em caso de sucesso, o backup anterior é **preservado** para recuperação
   manual e a nova Veylor é iniciada. O usuário pode examinar os backups
   `Veylor.rollback-*` ao lado do diretório de instalação.

### Limitações e segurança

- **Rollback automático cobre falha do instalador ou do marcador.** Ainda
  **não é um watchdog de saúde** do app: travamentos que ocorram depois da
  instalação bem-sucedida exigem recuperação manual do backup. A restauração
  do diretório não reverte alterações externas do Windows Installer/registro.
- SHA-256 detecta corrupção e divergência com o manifesto da release; **não
  equivale à autenticação de editor do Windows**. A origem confiável é o
  controle de publicação de Releases do repositório oficial. Proteja o GitHub
  com 2FA, revisão de mudanças e permissões mínimas.
- Não altere os backups enquanto o app estiver instalado; não compartilhe os
  caminhos privados de staging. O app nunca desativa SmartScreen nem verifica
  a origem por certificado inexistente.
- Arquivos individuais do app, diretórios de usuários, banco de dados e
  serviços do Render/PostgreSQL não são modificados pelo atualizador.
- A V0.3.6 **não** deve ser promovida como estável até CI verde e instalação,
  atualização e rollback testados em Windows real, inclusive com instalação
  personalizada. No Android não há instalação automática por este mecanismo.

## Como testar na branch

```powershell
cd apps/client
flutter create --project-name veylor --platforms=windows .
flutter pub get
flutter analyze --no-fatal-infos
flutter test
flutter build windows --release
dart compile exe tool/windows_update_runner.dart -o build/windows/x64/runner/Release/veylor-updater.exe
```

No GitHub Actions, o workflow `Veylor preview builds` faz testes do
instalador em runner Windows, incluindo digest incorreto, rollback de
pós-verificação e instalação válida. `Veylor beta Releases` publica
somente commits em `main` após todos os checks exigidos, sem alterar
automaticamente o Render.
