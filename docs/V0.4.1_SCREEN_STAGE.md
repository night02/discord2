# Veylor V0.4.1 — Palco de transmissão

Esta atualização melhora apenas a experiência do cliente. **Não altera
Render, PostgreSQL, OAuth ou LiveKit Cloud**.

- Se houver uma transmissão de tela ativa e assinada via LiveKit, o vídeo vai
  para o **palco maior** com o nome de quem transmite.
- Participantes e suas câmeras continuam em **miniaturas abaixo do palco**.
  A mesma transmissão não é duplicada em miniatura.
- No desktop a divisão é 7:4 palco/miniaturas; em janela compacta/celular,
  6:4. A lista de participantes continua rolável.
- Quando não há transmissão, a sala volta automaticamente à grade normal.
- Transmissões de outras pessoas têm precedência sobre a sua, para reduzir
  o efeito espelho. Uma transmissão mutada/não assinada não ocupa o palco.
- Microfone, câmera, cancelamento de ruído e botão de sair continuam
  disponíveis enquanto o vídeo é exibido.

## Qualidade e limitações

A renderização usa as faixas recebidas pelo SDK LiveKit com
`adaptiveStream` e `dynacast`. O tamanho da tela não força a publicação de
2K/60FPS nem melhora artificialmente a taxa de bits. O publicador ainda tem
limite inicial de 1080p/15FPS para screen share. Performance, reconexão,
latência e áudio entre Windows e Android exigem teste em dois dispositivos
com serviço LiveKit configurado.

## Entrega e versão

- Código Flutter: `0.4.1+14`.
- Instalador e pacotes de prévia: `Veylor-v0.4.1-...`.
- A GitHub Action `Veylor preview builds` deve passar em Windows, Linux e
  Android, além de Flutter e testes da API. Um commit em `main` aprovado
  será publicado como uma nova prerelease, preservando as anteriores.
- Nenhuma alteração ou limpeza no Render nesta etapa.
