# Veylor V0.3.4 — canais de download e atualizações seguras

## Origem oficial

Repositório privado dos downloads: **[night02/discord2](https://github.com/night02/discord2)**. O antigo Night0231-creator/discord2 continua preservado, mas a V0.3.4 confia **somente** em links da nova conta.

- Site de builds: https://github.com/night02/discord2/actions
- Releases beta: https://github.com/night02/discord2/releases (apenas após uma publicação manual bem-sucedida)
- API existente: https://veylor-postgres-staging.onrender.com

## Implementado

- O app confere versões pelo servidor HTTPS oficial. Sem enviar token bearer durante a consulta.
- O cliente compara o número de build instalado com o anunciado antes de apresentar a atualização.
- Só são aceitas páginas HTTPS do repositório privado `night02/discord2` em `/actions/runs/<ID numérico>` ou `/releases/tag/vX.Y.Z-beta`. Não permite links diretamente a binários, redirecionadores, domínios parecidos, query strings, autenticação na URL nem portas alternativas.
- O número de versão embutido na URL de uma release deve corresponder ao número de versão devolvido pela API.
- Os downloads continuam manuais: abrir a página oficial, autenticar no GitHub, baixar ZIP/EXE/APK, validar e instalar. **Não existe execução remota silenciosa.**
- O workflow de GitHub Releases só pode publicar após os testes Flutter, SQLite/PostgreSQL, saúde da API e os três builds passarem para o mesmo SHA. A release é prerelease privada e traz arquivo de checksums SHA-256.

## Como ativar as atualizações no Render

**Não atualizar o serviço do Render antes de verificar os artefatos realmente disponíveis.** O repositório de código não serve como prova de que o APK está pronto.

1. Execute os testes de CI da V0.3.4 e confira os artefatos para Android, Windows e Linux.
2. Após passar em testes de campo no PC + Android, incorpore o Pull Request ao branch principal do repositório novo.
3. Execute manualmente `Veylor beta Releases` com o Run ID do build aprovado, selecionando o branch do commit testado. Não reescreva tags beta existentes.
4. Verifique se a prerelease `v0.3.4-beta` existe, contém os arquivos esperados e os checksums SHA-256 batem.
5. Só então atualize os manifestos `apps/server/mobile-release.json` e `apps/server/windows-release.json` para **0.3.4+8**, apontando à página `https://github.com/night02/discord2/releases/tag/v0.3.4-beta` e faça deploy manual do backend correspondente.
6. Faça um smoke test externo `/health`, `/api/updates/android`, `/api/updates/windows` e teste login/canais/DM antes de dar por finalizada a troca.

**Migração dos aplicativos anteriores:** versões até a V0.3.3 só reconhecem o antigo repositório nos links de atualização. Quem já usa essas versões precisará instalar a V0.3.4 manualmente **uma única vez**, para passar a receber anúncios da nova conta GitHub.

## Segurança e limitações

- O GitHub é privado: apenas pessoas com acesso ao repositório conseguem baixar os pacotes. Não disponibilize links privados a público amplo.
- APKs debug anteriores podem ter assinatura diferente da V0.3.4 e exigir desinstalação. A versão Android com assinatura estável requer chaves de release cadastradas em GitHub Secrets; nunca enviar as chaves por chat ou commit.
- O instalador Windows ainda não tem assinatura de código Authenticode. Não desative SmartScreen/antivírus.
- A conta nova no GitHub não muda o banco PostgreSQL. O banco gratuito do Render expira em 11/11/2026 — faça backup e migração antes disso.
- Testes de CI simulam dispositivos e backend; não substituem verificação manual em Windows/Android reais.
