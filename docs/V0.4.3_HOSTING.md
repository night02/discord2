# Veylor V0.4.3 — hospedagem e mensagens de conexão

O cliente agora trata respostas de hospedagem sem JSON. `404 Not Found`
vira **Servidor não encontrado**, enquanto falhas de rede, timeout e páginas
de proxy viram mensagens legíveis. O status HTTP é preservado: apenas uma
falha de autenticação pode invalidar a sessão salva; indisponibilidade não
apaga as credenciais locais. Respostas normais da API mantêm sua mensagem de
validação (inclusive tamanho da senha no cadastro).

## Infraestrutura preparada

- Repositório: `night02/discord2`, branch `main`.
- Web Service: `veylor-postgres-staging`, região Virginia, plano gratuito.
- URL esperada do cliente: `https://veylor-postgres-staging.onrender.com`.
- Banco existente: `veylor-v2-postgres` no mesmo workspace e região.
- `render.yaml` conecta o banco por `fromDatabase`, sem copiar a senha para git.
- `REQUIRE_POSTGRES=1` impede criar um SQLite efêmero por falta de configuração.
- O Blueprint usa `/health` e implantação condicionada à aprovação dos checks.

O serviço foi criado pela integração. Aplicar o Blueprint no Dashboard é a
etapa que resolve a referência privada `DATABASE_URL`; até isso ocorrer,
o serviço não deve ser considerado online. O PostgreSQL existente não é
recriado nem gerenciado pelo Blueprint.

## Configuração e aceite

1. Aplicar o Blueprint usando o serviço e banco existentes no My Workspace.
2. Verificar `/health`: HTTP 200, `status=ok` e `storage=postgres`.
3. Verificar `/api/me` sem sessão: HTTP 401.
4. Configurar Discord no Developer Portal com Redirect URI exata:
   `https://veylor-postgres-staging.onrender.com/api/auth/discord/callback`.
   Guardar `DISCORD_CLIENT_ID` e `DISCORD_CLIENT_SECRET` apenas no ambiente do serviço.
5. Configurar `LIVEKIT_URL`, `LIVEKIT_API_KEY` e `LIVEKIT_API_SECRET` apenas no serviço.
6. Validar login Discord e chamada Windows/Android com usuários de teste autorizados.

Os segredos Discord/LiveKit não estão no Blueprint. A API pode funcionar com
login por senha antes de habilitar essas integrações. Não publicar credenciais
no chat ou GitHub. O plano gratuito do banco possui vencimento mostrado no
Dashboard; revisar a retenção antes de usar esta infraestrutura de teste
para dados duradouros.

## Validação da versão

Testes cobrem o erro da imagem enviada, páginas HTML de proxy, erros JSON de
validação, requisições HTTP locais e conexão recusada sem perder a sessão.
Versão cliente/instalador `0.4.3`; a beta só é publicada com todos os checks
e builds Windows/Android/Linux aprovados. A publicação do instalador, por si
só, não certifica que a configuração do Dashboard foi concluída.

Os endpoints de atualização consultam as betas públicas do repositório oficial,
conferem o build aprovado em main e usam o número real do pacote. O catálogo
fica em cache por dez minutos; falhas mantêm o último snapshot ou a beta
V0.4.2 já publicada, sem instalar nada automaticamente.
