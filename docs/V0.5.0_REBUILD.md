# Veylor V0.5.0 — reconstrução

O cliente foi separado em sessão, mensagens, WebSocket, chamada, atualização e
apresentação. A interface concentra DMs na área inicial e canais dentro de cada
servidor, com adaptação para PC e celular. A chamada pertence ao aplicativo:
navegar não encerra voz, câmera ou transmissão.

Microfone e câmera entram desligados. Os controles refletem as publicações reais.
Tela/janela exige seleção. Todos os perfis são liberados: 720p/30, 1080p/30,
1080p/60 experimental e 1440p/30 experimental. Captura e encoder recebem os
mesmos limites. Estatísticas WebRTC são medidas; não são os valores solicitados.

Caches e rascunhos são separados por conversa e limpos ao trocar de conta.
Respostas atrasadas não substituem outra conversa. Falhas de envio reutilizam
o identificador para evitar duplicação. Indisponibilidade preserva a sessão salva.

Os testes cobrem respostas atrasadas, interrupção de restauração, nonce de
reenvio, paginação, isolamento DM/canal/contas e chamada durante navegação.
O layout é testado em 320×568, 390×844, 640×360, 1024×768 e 1440×900.

A API usa uma emissão de credenciais de mídia comum a SQLite/PostgreSQL.
Rotas verificam associação ao servidor e canal antes de emitir um token
limitado àquela conta/sala, sem administração da sala. Há limite de solicitações.

O teste Media SFU loopback usa servidor 1.13.9 verificado por SHA-256 e SDK
nativo 1.1.0. Conecta duas contas na mesma sala e uma terceira em outra.
Confere PCM nos dois sentidos, vídeo decodificado, isolamento e parada de
publicação. Usa apenas frames sintéticos, loopback e credenciais de teste.
A verificação não captura equipamentos e não certifica Windows/Android/60 FPS.

A V0.4.3 publicada foi preservada. Render, dados e contas não foram apagados.
Atualizador Windows com SHA-256, confirmação, backup e rollback foi mantido.
A nova beta exige API SQLite/PostgreSQL, Flutter, SFU e builds aprovados no
mesmo commit. Não publicar como estável antes do teste em aparelhos reais.

Para aceite: configurar API HTTPS e LiveKit WSS, entrar com duas contas em
Windows/Android e dois PCs, conferir áudio, câmera, tela/janela, navegação,
desconexão, retomada e uso de CPU/FPS. Medir 1080p/30 antes de comparar 60 FPS.

Pendências: áudio do jogo no Windows, captura de tela Android/Linux e
supressão por IA no Windows/Linux. A interface não apresenta esses recursos
como ativos. A beta Windows continua sem Authenticode enquanto não houver
certificado; Android permanece de teste enquanto a assinatura definitiva
não estiver configurada.

O ambiente local se desconectou no final da reconstrução. O código foi
recuperado pela integração GitHub; a validação final é a dos checks desta branch.
